# eval/

평가 자산(골든 데이터셋·지표) 공간입니다. 코드와 라이프사이클이 달라
`src/`가 아닌 별도 최상위 디렉토리로 분리합니다.

## 규칙

- **지표 함수는 순수 함수로**: (예측, 정답)만 받아 점수를 계산 — 구현이 바뀌어도
  재사용 가능하게 (`eval/metrics.py` 권장).
- **골든 데이터셋(`eval/golden_dataset/`)은 평가 기준 자체**: 신중히 변경하고
  이유를 커밋 메시지에 명시하세요.
- 골든셋 CSV는 `.gitignore`의 `!golden_dataset*.csv` 예외로 커밋 가능합니다
  (그 외 데이터 파일은 커밋 금지).
- **측정 결과 JSON은 예외로 커밋합니다.** 원본 데이터가 아니라 *주장의 근거*라
  그렇습니다. 실측값을 문서에 인용해놓고 그 숫자가 어디서 나왔는지 남기지 않으면
  나중에 검증할 방법이 없습니다. 크기가 커지면(수백 KB) 이 예외를 다시 논의합니다.

# 패널 지표 (`panel_metrics.py`)

**현재 버전 V2** · 최종 수정 2026-08-14 · 담당 이수호

AI 손님 패널을 재는 순수 함수 모음. 외부 의존성 없음.

- `pearson` / `spearman` / `mean_absolute_error` — 사람 평가와의 일치도
- `price_contradictions` — 걸림돌 라벨의 자기모순 건수

위 규칙의 `metrics.py` 권장 이름 대신 `panel_metrics.py`를 쓴다. 생성 파이프라인 쪽에도
별도 지표가 생길 예정이라 파트별로 파일을 나눈다.

## 쓰는 곳

팀원이 광고 시안을 블라인드로 5점 평가한 값을 정답으로 놓고, 패널 점수와의 상관을 본다.
**"이 평가를 믿어도 되나"에 대한 유일한 외부 근거**라 발표 자료에 그대로 들어간다.
라벨은 모이는 대로 `eval/golden_dataset/`에 둔다.

`price_contradictions` 는 **"가격이 괜찮다고 해놓고 걸림돌은 price"** 인 코멘트를
센다. 쏠림 자체는 결함이 아니다 — 정말 비싼 광고면 맞는 답이고, 광고에 가격 말고
구체적인 게 없으면 손님이 반응할 것도 가격뿐이다. 결함인 것은 이 모순이다.

## 알려진 제약

낱말 맞추기라 완벽하지 않다. **판정이 아니라 계기판으로 쓴다.** 첫 판은 낱말
줄기(`"적당"`)만 봐서 실측에서 5건을 잡았는데 **5건 다 오탐**이었다 —
`"가격이 적당한지 고민"`(판단 유보)과 `"가격이 적당하다"`(단정)를 못 갈랐다.
지금은 단정형 어미까지 본다. **낱말을 늘리기 전에 테스트의 실측 코멘트로
반드시 확인할 것.** 놓치는 쪽으로 기울여 두었다 — 잘못 울리는 계기판은
안 울리는 것보다 나쁘다.

# 재생성 A/B (`run_ab_panel.py` · `ab_panel.json`)

**현재 버전 V1** · 2026-08-12 · 담당 이아인

패널 제안을 반영해 다시 만든 광고가 **실제로 나아지는가**를 잰다. 루프가 도는 것은
확인했지만 낫게 만드는지는 확인한 적이 없었고, 그게 이 제품의 핵심 주장이다.

- **심판은 `contrast.py` 의 `fit`** — LLM 이 아니라 서울시 실측 수치로 계산하는
  결정적 함수라 자기가 만든 것을 자기가 칭찬할 수 없다. LLM 에게 "좋아졌니?"를
  되묻는 순환 평가를 피하는 것이 설계의 핵심이다.
- **개선과 회피를 가른다** — 시점 언급을 지워 감점을 피한 것도 점수는 오른다.
  `weakest()` 가 `fit is None` 인 항목을 빼기 때문이다. 채점된 항목 집합을 같이
  기록해 항목이 사라진 경우를 따로 센다.
- **대조군을 둔다** — 패널 제안 대신 `copy_gen.REVISION_OPTIONS` 의
  "아예 다른 느낌으로"로 재생성한다. 없으면 *재생성 자체*의 효과와 *패널*의 효과를
  구분할 수 없다.

`ab_panel.json` 은 광고 1건당 한 행이고, 필드는 이렇다.

```
store area category product price
before  {headline sub weak weak_kind scored}    ← scored 는 fit 이 붙은 항목만
panel   {같은 구조}      control {같은 구조}
suggestions top_resistance confidence excluded_cnt
verdict_panel verdict_control secs
```

## 실측 결과 (2026-08-12, 광고 9건 · 실제 호출 189회)

**패널 9건 전부 "변화 없음". 대조군도 동일.** 다만 이것은 *패널이 효과 없다*는 뜻이
아니라 **심판이 패널이 바꾸는 것을 못 본다**는 뜻이다. 축이 안 겹친다.

| 축 | 가동 여부 |
|---|---|
| `price` | `brief.price` 로만 계산 → `revised()` 가 슬롯을 안 바꾸므로 **구조적으로 고정** |
| `timing` | 문구에 시점 말이 있어야 채점 → 패널 제안이 시점을 건드린 적 **0/18** |
| `weekend` | 같음 → **1/18** (그마저 사장님이 `situation` 에 쓴 말) |

9건 중 6건은 채점된 항목이 `price` 하나뿐이었다. 즉 재생성이 무엇을 하든
숫자가 못 움직이는 상태였다.

원인은 `evaluator._summarize` 가 모델에게 주는 "사실" 블록이 **가격 두 줄뿐**이라는
것이다. 시간대·주말·경쟁 수치는 `contrast()` 가 `_summarize` 호출 7줄 앞에서 이미
만들어두는데 넘어가지 않는다. 최악 시간대(매출 0.0%)를 대놓고 말하는 문구를 손으로
넣어봐도 제안은 가격 얘기였고, 유일한 시점 언급은 *"아침 메뉴라는 점을 강조하며"* —
아침 매출이 0.0% 인 동네에서 **방향이 반대**였다.

# 판별력 측정 (`accuracy.py`)

**현재 버전 V2** · 최종 수정 2026-08-13 · 담당 이수호

패널이 **좋은 광고와 나쁜 광고를 구분하는가**를 잰다.

정확도를 못 재면 개선을 말할 수 없다. 그런데 "실제 손님 반응"이라는 정답이
우리에게 없다. 그래서 정답 대신 **순서**를 쓴다 — 어느 쪽이 나은지 사람이면
이견 없이 답할 수 있는 광고 쌍을 만들어, 패널이 그 순서를 맞추는지 본다.

**판별력이 낮으면 점수는 노이즈다.** 쌍을 못 가르는데 절대 점수가 62.4 라고
말하는 것은 의미가 없다. 이 지표가 먼저다.

## 쌍은 실측에서만 만든다

역삼역 2026Q1 수치(점심 매출 47.9% · 객단가 9,546원 · 30대 38.2%)에서 벗어난
쪽이 "나쁜 광고"다. 취향으로 만든 쌍은 패널이 틀려도 **패널 탓인지 우리 탓인지
알 수 없다.**

| 쌍 | 갈래 | 무엇을 가르나 |
|---|---|---|
| 시간대 | 상권 | 매출이 몰리는 시간을 짚었는가 |
| 가격 | 상권 | 객단가에 맞는 가격인가 |
| 타깃 | 상권 | 이 동네 주 고객층에 말하는가 |
| 명료성 | 보편 | 무엇을 파는지 알 수 있는가 |

## 쓰는 법

```bash
MODEL_PROFILE=openai python eval/accuracy.py                    # 판별력 (라벨 불필요)
MODEL_PROFILE=openai python eval/accuracy.py --sheet            # 사람 평가용 시트
MODEL_PROFILE=openai python eval/accuracy.py --score labels.csv # 사람과 대조
MODEL_PROFILE=openai python eval/accuracy.py --ablate standing  # 그 요소가 값을 하는가
MODEL_PROFILE=openai python eval/accuracy.py --k 3              # 자기일관성 표본 수
```

`--sheet` 는 광고를 섞어 익명 키(`sha1[:8]`)로 내보낸다. 사람이 채점할 때
어느 쪽이 "좋은 쪽"인지 보이면 안 되기 때문이다 — 아인님 지적으로 추가했다.

`--ablate` 는 프롬프트 요소 하나를 빼고 같은 측정을 돌린다. **값을 못 하는
요소는 지운다는 전제**로 넣었다.

## 실측 결과

```

                             판별 4/4 유지
재실행 흔들림                 0.1~3.1점 — 3점 미만 차이는 해석하지 말 것
```

## 알려진 제약

- 쌍이 4개뿐이고 상권 1곳(역삼)이다. 다른 상권·업종은 안 봤다.
- "사람이면 이견 없이 답한다"는 전제 자체를 검증하지 않았다. `--sheet`/`--score`
  가 그 검증용인데 라벨이 아직 없다.

# 패널 실측 (`run_panel_eval.py`)

**현재 버전 V2** · 최종 수정 2026-08-14 · 담당 이수호

실제 LLM 으로 패널 평가를 한 번 돌려 **탈락률·점수·걸림돌 분포**를 본다.
단위 테스트는 전부 `FakeClient` 라서, 모델이 규칙을 실제로 지키는지는 돌려봐야 안다.

DuckDB 를 안 쓴다 — 골든 픽스처를 그대로 읽으므로 ETL 없이 돌아간다.
**한 번에 14콜**(손님 12 + 걸림돌 분류 1 + 제안 요약 1).

## 쓰는 법

```bash
MODEL_PROFILE=openai python eval/run_panel_eval.py
MODEL_PROFILE=openai python eval/run_panel_eval.py --runs 3        # 재현성
MODEL_PROFILE=openai python eval/run_panel_eval.py --no-summary    # 요약 콜 끄기
MODEL_PROFILE=openai python eval/run_panel_eval.py --price 0       # 가격 없는 광고
MODEL_PROFILE=openai python eval/run_panel_eval.py \
  --product 아메리카노 --headline "점심 10분 컷, 아메리카노" --sub "..."
```

`--price 0` 은 "가격 없음"이다(`AdBrief.show_price`). **걸림돌이 입력에 반응하는지
재는 결정적 시험** — 적히지도 않은 가격을 걸림돌로 고르면 광고를 안 본 것이다.

문구와 상품이 어긋나면 경고를 띄운다. 어긋난 입력으로 잰 결과는 못 믿는다.

## 실측 결과 (2026-08-14)

걸림돌이 무엇을 보고 정해지는지를 6회에 걸쳐 좁혔다.

광고                avg_ticket  걸림돌 결정자   price
크로플 9,500원          줌       손님 콜        12/12

마지막 줄은 앞줄과 **광고도 같고 준 숫자도 같다.** 누가 라벨을 고르느냐만 다르다.
근거로 인용할 수 있는 숫자가 라벨을 정하고 있었다.

## 알려진 제약

- 상권 1곳(역삼) · 광고 4건 · 각 1회다. 재현성은 `--runs` 로 따로 봐야 한다.
- 골든 픽스처가 12명 전원 `price_sens=mid` 라 가격 축은 아직 검증 불가.
  픽스처 재생성이 필요하다(A 파트).
