# eval/

평가 자산(골든 데이터셋·지표) 공간입니다. 코드와 라이프사이클이 달라
`src/`가 아닌 별도 최상위 디렉토리로 분리합니다.

## 규칙

- **지표 함수는 순수 함수로**: (예측, 정답)만 받아 점수를 계산 — 구현이 바뀌어도
  재사용 가능하게 (`eval/metrics.py` 권장).
- **골든 데이터셋(`eval/golden_dataset/`)은 평가 기준 자체**: 신중히 변경하고
  이유를 커밋 메시지에 명시하세요.
- 골든셋 CSV는 `.gitignore`의 `!golden_dataset*.csv` 예외로 커밋 가능합니다
  (그 외 데이터 파일은 커밋 금지).
- **측정 결과 JSON은 예외로 커밋합니다.** 원본 데이터가 아니라 *주장의 근거*라
  그렇습니다. 실측값을 문서에 인용해놓고 그 숫자가 어디서 나왔는지 남기지 않으면
  나중에 검증할 방법이 없습니다. 크기가 커지면(수백 KB) 이 예외를 다시 논의합니다.

# 패널 지표 (`panel_metrics.py`)

**현재 버전 V1** · 최종 수정 2026-08-06 · 담당 이수호

AI 손님 패널의 점수가 실제 사람 평가를 얼마나 따라가는지 재는 순수 함수 모음.
`pearson` / `spearman` / `mean_absolute_error`, 외부 의존성 없음.

위 규칙의 `metrics.py` 권장 이름 대신 `panel_metrics.py`를 쓴다. 생성 파이프라인 쪽에도
별도 지표가 생길 예정이라 파트별로 파일을 나눈다.

## 쓰는 곳

팀원이 광고 시안을 블라인드로 5점 평가한 값을 정답으로 놓고, 패널 점수와의 상관을 본다.
**"이 평가를 믿어도 되나"에 대한 유일한 외부 근거**라 발표 자료에 그대로 들어간다.
라벨은 모이는 대로 `eval/golden_dataset/`에 둔다.

## 알려진 제약

`eval/`은 src 레이아웃 밖이라 설치 대상이 아니고, 그대로는 import 되지 않는다.
현재는 `tests/conftest.py`가 `sys.path`에 넣어 우회한다.
팀 합의 후 `pyproject.toml`의 `[tool.pytest.ini_options] pythonpath`에 `"eval"`을
추가하면 그 우회는 지워도 된다.

# 재생성 A/B (`run_ab_panel.py` · `ab_panel.json`)

**현재 버전 V1** · 2026-08-12 · 담당 이아인

패널 제안을 반영해 다시 만든 광고가 **실제로 나아지는가**를 잰다. 루프가 도는 것은
확인했지만 낫게 만드는지는 확인한 적이 없었고, 그게 이 제품의 핵심 주장이다.

- **심판은 `contrast.py` 의 `fit`** — LLM 이 아니라 서울시 실측 수치로 계산하는
  결정적 함수라 자기가 만든 것을 자기가 칭찬할 수 없다. LLM 에게 "좋아졌니?"를
  되묻는 순환 평가를 피하는 것이 설계의 핵심이다.
- **개선과 회피를 가른다** — 시점 언급을 지워 감점을 피한 것도 점수는 오른다.
  `weakest()` 가 `fit is None` 인 항목을 빼기 때문이다. 채점된 항목 집합을 같이
  기록해 항목이 사라진 경우를 따로 센다.
- **대조군을 둔다** — 패널 제안 대신 `copy_gen.REVISION_OPTIONS` 의
  "아예 다른 느낌으로"로 재생성한다. 없으면 *재생성 자체*의 효과와 *패널*의 효과를
  구분할 수 없다.

`ab_panel.json` 은 광고 1건당 한 행이고, 필드는 이렇다.

```
store area category product price
before  {headline sub weak weak_kind scored}    ← scored 는 fit 이 붙은 항목만
panel   {같은 구조}      control {같은 구조}
suggestions top_resistance confidence excluded_cnt
verdict_panel verdict_control secs
```

## 실측 결과 (2026-08-12, 광고 9건 · 실제 호출 189회)

**패널 9건 전부 "변화 없음". 대조군도 동일.** 다만 이것은 *패널이 효과 없다*는 뜻이
아니라 **심판이 패널이 바꾸는 것을 못 본다**는 뜻이다. 축이 안 겹친다.

| 축 | 가동 여부 |
|---|---|
| `price` | `brief.price` 로만 계산 → `revised()` 가 슬롯을 안 바꾸므로 **구조적으로 고정** |
| `timing` | 문구에 시점 말이 있어야 채점 → 패널 제안이 시점을 건드린 적 **0/18** |
| `weekend` | 같음 → **1/18** (그마저 사장님이 `situation` 에 쓴 말) |

9건 중 6건은 채점된 항목이 `price` 하나뿐이었다. 즉 재생성이 무엇을 하든
숫자가 못 움직이는 상태였다.

원인은 `evaluator._summarize` 가 모델에게 주는 "사실" 블록이 **가격 두 줄뿐**이라는
것이다. 시간대·주말·경쟁 수치는 `contrast()` 가 `_summarize` 호출 7줄 앞에서 이미
만들어두는데 넘어가지 않는다. 최악 시간대(매출 0.0%)를 대놓고 말하는 문구를 손으로
넣어봐도 제안은 가격 얘기였고, 유일한 시점 언급은 *"아침 메뉴라는 점을 강조하며"* —
아침 매출이 0.0% 인 동네에서 **방향이 반대**였다.

## 알려진 제약

- **PR #8 머지 전에는 `run_ab_panel.py` 의 import 가 실패한다** (`schema.Feedback`·
  `AdBrief.revised()` 가 그 PR 에 있다). 측정은 그 브랜치에서 돌렸다.
  `eval/` 은 CI 범위 밖이라 검사를 깨지는 않는다.
- 표본 9건. 비율이 아니라 건수로 읽어야 한다.
- 좌표를 박아 지오코딩을 건너뛰는데, "수유동" 좌표가 실제로는 **도봉산입구** 상권에
  매칭된다. A/B 는 같은 상권을 전후로 쓰므로 결과에 영향은 없지만 가게 이름이 오해를 준다.
