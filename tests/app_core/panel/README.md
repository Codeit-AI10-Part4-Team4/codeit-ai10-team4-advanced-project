# tests/app_core/panel/

**현재 버전 V6** · 최종 수정 2026-08-11 · 담당 이수호

`src/app_core/panel/`의 결정적 로직 테스트. 구조는 `src/`를 미러링한다(AGENTS.md).

## 무엇을 테스트하고, 무엇을 하지 않는가

**한다** — 피처 스키마 계약, 근거 대조, 가중 집계, 지표 함수. 전부 입력이 같으면
출력이 같은 로직이다.

**한다 (F5 추가)** — `FakeClient` 로 LLM 응답을 지정해 **거르는 쪽**을 검증한다.
스키마가 깨졌을 때·수치를 지어냈을 때 1회만 재시도하는지, 재시도가 성공하면
살리는지, 프롬프트에 인용 금지 필드가 새어 들어가지 않는지. 콜 횟수도 센다 —
예산이 걸려 있어서(07 R4) 한 명당 1콜 + 요약 1콜이어야 한다.

**하지 않는다** — LLM 출력 자체. 응답이 매번 달라 고정할 수 없고, 고정하면
그 시점 모델에만 맞는 테스트가 된다. **검증 게이트(`evidence_match`·스키마 강제)가
런타임 테스트 역할**을 하므로 우리가 테스트할 것은 그 게이트다.

외부 API 호출도 하지 않는다. 비용과 비결정성 때문이며, 필요하면 mock을 쓴다.

## 골든 픽스처

`tests/fixtures/features_yeoksam_20261.json`은 **아인님이 CSV 실물 검수 후 만든 역삼역 2026Q1 실측 산출물**이다. 아인님 소유 파일이라 수정하지 않는다.
가상의 예시가 아니라 A→B 계약의 실물이라, 이게 파싱되지 않으면 계약이 깨진 것이다.

`test_schemas.py`가 이 파일에 대해 검증하는 것:

- `gender_share`·`age_share`·`time_share`·`foot_age_share`·`weight` 각각 합이 1.0
- **페르소나 가중치가 `gender_share × age_share` 곱인지** — 07 §4.4①의 독립 가정.
  어긋나면 가중 평균이 상권 구성을 반영하지 못한다
- 근거가 곱한 값이 아니라 **원본 두 축을 각각 인용**하는지
- `weekend` 유형이 `weekend_ratio > 0.4`일 때만 나오는지 (역삼역 0.138 → 없어야 함)
- 폐기된 경로(`sales_share.*`·`time_traffic.*`)가 근거 대조에서 탈락하는지
- **매칭·데이터 품질 지표(`match_distance_m`·`demo_coverage`)가 `not_citable`로 막히는지**,
  그리고 금지 목록이 과하게 넓어져 상권 특성까지 막지는 않는지
- **배후지(`back_age_share`)가 `None`일 때 `resolve()`가 터지지 않는지** —
  발달상권에는 배후지가 없다
- 직장·상주인구·아파트 값이 스키마에서 **버려지지 않고 살아 있는지**

**픽스처를 갱신할 때는** 위 테스트가 깨지는지 먼저 보고, 깨지면 스키마와 픽스처 중
어느 쪽이 맞는지 아인님과 정한 뒤 커밋한다. 파일명은 CI 인코딩 문제를 피해 로마자로 쓴다.

## 규칙

- 파일명은 `test_<모듈>.py`로 `src/` 구조를 미러링한다.
- 픽스처는 `tests/fixtures/`에 두고 `tests/conftest.py`에서 로드한다.
- 파일을 추가·변경하면 **아래 표에 한 줄 추가하고 상단 버전을 올린다.**
