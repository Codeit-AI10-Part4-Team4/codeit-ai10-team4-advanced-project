# tests/app_core/panel/

**현재 버전 V1** · 최종 수정 2026-08-06 · 담당 이수호

`src/app_core/panel/`의 결정적 로직 테스트. 구조는 `src/`를 미러링한다(AGENTS.md).

## 무엇을 테스트하고, 무엇을 하지 않는가

**한다** — 피처 스키마 계약, 근거 대조, 가중 집계, 지표 함수. 전부 입력이 같으면
출력이 같은 로직이다.

**하지 않는다** — LLM 출력 자체. 응답이 매번 달라 고정할 수 없고, 고정하면
그 시점 모델에만 맞는 테스트가 된다. **검증 게이트(`evidence_match`·스키마 강제)가
런타임 테스트 역할**을 하므로 우리가 테스트할 것은 그 게이트다.

외부 API 호출도 하지 않는다. 비용과 비결정성 때문이며, 필요하면 mock을 쓴다.

## 골든 픽스처

`tests/fixtures/features_yeoksam.json`은 **아인님이 실제로 만들어 넘긴 산출물**이다.
가상의 예시가 아니라 A→B 계약의 실물이라, 이게 파싱되지 않으면 계약이 깨진 것이다.

`test_schemas.py`가 이 파일에 대해 검증하는 것:

- `sales_share`·`time_traffic`·`weight` 각각 합이 1.0
- **페르소나 가중치 합이 성별·연령 매출 비중을 정확히 분해**하는지
  (p01+p07 = M30 같은 관계. 어긋나면 가중 평균이 상권 구성을 반영하지 못한다)
- 경계 페르소나가 최소 1명 존재하는지 (없으면 저항 요인 다양성이 사라진다)
- `axes.time`에 `morning`·`afternoon`이 들어가는지 (enum을 3종으로 좁히면 여기서 터진다)

**픽스처를 갱신할 때는** 위 테스트가 깨지는지 먼저 보고, 깨지면 스키마와 픽스처 중
어느 쪽이 맞는지 아인님과 정한 뒤 커밋한다. 파일명은 CI 인코딩 문제를 피해 로마자로 쓴다.

## 규칙

- 파일명은 `test_<모듈>.py`로 `src/` 구조를 미러링한다.
- 픽스처는 `tests/fixtures/`에 두고 `tests/conftest.py`에서 로드한다.
- 파일을 추가·변경하면 **아래 표에 한 줄 추가하고 상단 버전을 올린다.**
