## 0. 근거표

## 0-1. 현재 코드 계약 (compose v2 가 받는 입력)

`pipeline.generate_ad` → `compose_ad(product, headline, sub, background)` 호출 시:

| 갈래 | product | background | compose 가 아는 것 |
|---|---|---|---|
| cutout | 청소된 누끼(RGBA) | 생성 배경 | 제품이 별도 레이어 → 위치·그림자 제어 가능 |
| keep | **None** | 원본 사진 | 제품 위치 모름 |
| generate / 사진 없음(hero) | **None** | 제품이 그려진 생성 장면 | 제품 위치 모름 — **keep 과 구분 불가** |

→ v2 규칙은 `product is None` / `not None` 두 경우로만 갈라진다. hero 전용 힌트(제품 위치 전달)는 v2.1.

## 1. 우리 것 vs 레퍼런스 — 무엇이 다른가 (실측)

| 항목 | 우리 골든셋 감성형 (현재) | 레퍼런스 18장 (근거표 집계) | 판정 |
|---|---|---|---|
| 글자 위치 | 항상 화면 정중앙 | 상단 8 · 상+하 4 · 하단 1 = **중앙 아닌 것 13/18**, 중앙 5/18 | ❌ 최대 원인 |
| 가독성 처리 | 흰 글자 + 두꺼운 갈색 외곽선을 **모든 문구에 일괄** | **전체 문구 두꺼운 외곽선 일괄: 0/18.** 배경 대비색 14 · 장식용 외곽선/그림자 4(WATERMELON·MANGO·Cappuccino·반복타이포) · 반투명 판 1 | ❌ 일괄 stroke 가 문제. 장식용 outline 은 금지 근거 없음 |
| 글자색 | 항상 흰색 | 배경 계열의 진한/연한 톤이 다수 (연분홍→진분홍, 진녹→크림, 흰→진홍) | ❌ |
| 배경 | AI 생성 사진(복잡) | **단색·파스텔 판 12/18**, 사진 5, 사진+판 1 | 🟡 poster형과 결이 같음 |
| 폰트 역할 | 1종, 크기만 다름 | 1종 9 · 2종 5 · 3종 4 = **2종 이상 9/18** | 🟡 절반. "2종이면 충분, 1종도 정석" |
| 색 개수 | 배경 무작위 + 흰 + 갈색 | **3색 이내 18/18** (2색 9 · 3색 8 · 1색 1) | ❌ 가장 강한 규칙 |
| 제품 위치 | 하단 중앙 | 중앙 9 · 하단 4 · 없음 3 | ✅ 비슷 |

**결론**: 사진 품질이 아니라 **①글자 위치 ②일괄 외곽선 ③색 통제** 세 가지가 "자동 전단지" 인상의 원인. 셋 다 compose.py 수정 범위.

## 2. compose v2 규칙

캔버스 1080×1080 기준. 비율로 적어 다른 규격(4:5 등)에도 적용.

### 2-1. 안전 영역 (글자 자리) — 상단형 / 하단형

```
상단형                                하단형
┌───────────────────┐  0%           ┌───────────────────┐  0%
│  [제목] y 8~19%    │               │                   │
│  [부제] 제목 아래   │  ← 글자 영역   │      제품/사진     │
├───────────────────┤  33%          │                   │
│                   │               ├───────────────────┤  67%
│      제품         │               │  [제목] y 72~84%  │
│   y 36~92%        │               │  [부제] 제목 아래   │
└───────────────────┘  100%         └───────────────────┘  100%
```

- 좌우 여백 **7%** (76px) — 글자·제품 모두 침범 금지
- 부제는 제목 바로 아래, 간격 = 제목 글자 높이 × 0.35
- **선택 규칙 (코드 계약 §0-1 기준)**
  - `product is not None` (cutout) → **상단형 고정** (제품이 아래 앉음)
  - `product is None` (keep · hero · generate) → 배경의 상단 1/3 과 하단 1/3 밝기 표준편차를 재서 **낮은 쪽**(단순한 쪽)에 글자. 임계값 불필요(상대 비교). hero 사진도 같은 규칙 — 제품이 어디 있는지 compose 는 모르므로 "덜 복잡한 쪽"이 최선의 추정

### 2-2. 긴 문구 처리

1. 제목: 시작 크기에서 폭 안에 안 들어가면 **크기 축소** (하한 5.5%)
2. 하한에서도 넘치면 **2줄로 줄바꿈** (공백 기준, 없으면 글자 수 절반). **최대 2줄**
3. 2줄로도 넘치면 **말줄임(…)** — 잘라내되 로그 남김
4. 부제 동일 규칙, 최대 2줄, 시작 크기 = 제목 × 0.42
5. 글자 영역 총 높이가 33% 를 넘으면 부제를 **1줄 말줄임**으로 (compose 는 의미를 축약할 수 없다 — 잘라낼 뿐)

### 2-3. 가독성 — "일괄 두꺼운 외곽선" 금지, 두 방식 중 자동 선택

| 방식 | 조건 | 구현 |
|---|---|---|
| **A. 대비색 글자** (기본) | 글자 영역 밝기 std ≤ **임계값** | 영역 평균 밝기 > 128 → 어두운 글자(#1A1A1A 계열), 아니면 밝은 글자(#FAFAFA 계열). **v2 는 흑/백 계열만** — 배경 hue 기반 색은 v2.1 |
| **B. 그라데이션 판** | 글자 영역 밝기 std > 임계값 | 글자 영역 뒤 검정 그라데이션, 불투명 0.55 → 0. **상단형: 위가 진하고 아래로 투명. 하단형: 아래가 진하고 위로 투명.** 높이 = 글자 영역 + 6%. 글자 흰색 |
| (허용) 장식 outline | 디자인 의도가 있을 때만 (v2 미구현) | 레퍼런스 4/18 — 얇은 동색 outline 등. 갈색 두꺼운 stroke 일괄은 금지 |

**임계값 실측 — 두 단계**:
1. `data/golden_complexity.csv` (원본 사진 기준, 15장 × 상·하단 = 30개): 최소 11.6 · Q1 35.0 · 중앙값 43.95 · Q3 54.9 · 최대 85.6 → 임시값 55.
   ⚠️ 그런데 **cutout·generate 갈래는 글자가 원본이 아니라 AI 생성 배경 위에 얹힌다.** 원본 기준 측정은 keep 갈래에만 유효.
2. `data/golden_bg_v2_stats.csv` (compose 가 실제로 받은 배경 스냅샷 `data/golden_bg_v2/` 기준, 15행): 55 에서 판 5장 → **50 에서 7장**. 바뀌는 2장이 정확히 육안 문제였던 꽃집_밝음(std 53.5)·꽃집_복잡(50.5).
   → **확정 임계값 50.** 분식_밝음(keep, 하단 std 36.7)은 50 에서도 판 없음 — 나뭇결 텍스처 위 검은 글자가 답답한 건 v2.1 지배색 과제로 보류.
   평균 밝기 차이 보조 조건은 계산상 꽃집을 못 잡아 채택하지 않음(복잡도만 늘림).

### 2-4. 폰트 역할

- **제목**: `display` 역할 — 시작 크기 캔버스 폭의 **8.5%**(92px), 하한 5.5%
- **부제**: `body_light` 역할 — 제목 × 0.42
- 세 번째 텍스트(가격·라벨)는 부제와 같은 역할 → **역할 최대 2종** (레퍼런스: 1종 9 · 2종 5 · 3종 4)
- 자간 조정은 **v2 범위 밖** — PIL 은 자간을 직접 지원하지 않아 글자 단위 그리기가 필요. 필요해지면 v2.1 에서 별도 구현

**재현성 문제 (미결)**: `assets/fonts`(BlackHanSans·NotoSansKR·NanumPenScript, 전부 OFL)는 현재 **untracked**.
다른 환경에선 display/body_light 가 같은 OS 폰트(맑은고딕 볼드)로 폴백돼 역할 분리가 사라진다. 제안 2안:
- **(A) 폰트 동봉** — OFL 라이선스라 커밋 가능, 총 용량 확인 필요(NotoSansKR 2종이 큼). 별도 PR로, `assets/fonts/` 만 명시 add. `git add -A` 금지
- **(B) 역할별 OS 폴백 분리** — fonts.py `_OS_FALLBACK` 을 역할별로 나눠 display=맑은고딕 볼드, body_light=맑은고딕 일반 등. 동봉 없이도 "굵기 차이"는 남음
- 권장: **A + B 둘 다** (A 가 본선, B 가 보험). 결정은 팀(아인님 #18 지적 사항).

### 2-5. 색 — 3색 이내

- 배경(1) + 글자(1) + 강조(1). 강조색은 가격·할인 뱃지에만
- v2 범위: 글자색은 §2-3 A 규칙(밝기 기반 흑/백 계열)까지만
- v2.1: 사진 지배색 → 같은 hue 의 진한/연한 톤 (Strawberry Latte·MATCHA 방식)

### 2-6. 제품 합성 (`product is not None` = cutout 만)

- **사용 가능 상자** 계산이 먼저: 세로 = (글자 영역 하단 + 3%) ~ (캔버스 하단 − 8%), 가로 = 좌우 7% 안쪽
  - 상단형이면 글자 영역 하단 ≈ 33% → 상자 세로 36% ~ 92% (캔버스 높이의 56%)
- 제품은 **이 상자 안에 들어가도록 축소** (`thumbnail`) — 상자 하단에 붙이고 가로 중앙. 최대 폭 75% 는 상자 가로가 이미 86% 라 별도 제한 불필요
- "밀기"는 없다 — 제품은 애초에 하단에 붙어 있어 더 밀 곳이 없다. 충돌 회피는 전부 축소로
- 바닥 그림자: 누끼 하단 타원 — 폭 제품 × 0.9, 높이 제품 높이 × 0.06, 검정 불투명 0.25, blur 24px. **hero 는 제품이 배경에 이미 그려져 있어 그림자를 못 얹는다** — cutout 전용

## 4. 검증 방법 (두 갈래)

- **(1) 절대 평가**: 골든셋 15장 v2 재실행 → 팀 3명이 "인스타에 올릴 수 있다/없다" 이진 투표. 현재 약 10/15 (개발 중 정성 평가). 목표는 숫자로 못 박지 않고 **v1 대비 개선 여부**로 본다
- **(2) 쌍대 비교 (권장, 블라인드)**: 같은 평가자가 두 이미지를 나란히 보고 나은 쪽 선택 — 15장 × 3명 = 45표. **어느 쪽이 v2 인지 표기하지 않고, 좌우 배치를 사진마다 무작위로 섞는다** (평가 시트를 만드는 스크립트가 배치를 기록해두고 채점 때 복원). "v2 선호 ≥ 70%" 면 채택. 절대 점수보다 잡음에 강하다 (아인님 패널 설계와 같은 논리)
- 육안 보정 결과: §2-3 임계값을 55 → **50** 으로 확정 (실제 배경 스냅샷 기준, 꽃집 2장 해결). 추가 오판이 나오면 같은 절차로 재조정
- ⚠️ **공정 비교 조건**: 생성 배경은 실행마다 달라지므로(sd-turbo seed 미고정), v1/v2 비교는 **동일한 pre-compose 재료(배경·제품 누끼·문구)를 저장해 두 버전에 똑같이 넣어** 만든다. 배경까지 다른 비교는 조판 효과의 증거가 아니다. seed 고정은 gen_background 별도 PR

## 5. 레퍼런스 출처·사용 범위

`references.csv`(출처·이유) + `reference_analysis.csv`(장별 판정). 내부 분석용이며 원본은 커밋·배포·학습에 쓰지 않는다. 발표 노출 시 사전 허락 (구뜨몽떼는 지인 — 별도 확인 예정).
