## 3. 챗봇

### 3-1. 입력 방식

자연어 입력을 기본 경로로 하며, 선택지는 보조 수단으로 제공한다.

- 입력창에 예시 문구를 **플레이스홀더**로 표시한다 (실제 입력값이 아닌 회색 안내 문구)
  - `예: 크로플 신메뉴를 홍보하고 싶어 인스타에 올릴 사진 만들어줘`
- 선택지 클릭은 **필수가 아니다.** 자연어로 답변해도 되며, 표현이 어려울 때만 사용한다

### 3-2. 선택지 구성

| 단계 | 생성 주체 | 내용 |
|---|---|---|
| 1단계 | **고정** | `[광고 이미지 만들기]` `[광고 문구 만들기]` |
| 2단계 이후 | **LLM** | 대화 맥락에 따라 매 턴 동적으로 생성 |

2단계 이후를 LLM 이 선택지를 생성하는 근거는 다음과 같다. 상황별로 확인해야 할 항목이
달라 선택지를 사전에 열거할 경우 경우의 수를 감당할 수 없으며, 목록에 없는
상황이 발생하면 대응이 불가능하다.

### 3-3. LLM 응답 형태

매 턴 **메시지와 선택지를 함께** 반환한다.

```
{ "message": "어떤 느낌으로 만들어드릴까요?",
  "options": ["따뜻하게", "깔끔하게", "눈에 띄게"] }
```

### 3-4. 개발용 표시

**개발 단계에서는 화면 우측에 주문서를 매 턴 노출한다.** LLM 이 사용자 의도를
정확히 해석했는지 육안으로 검증하기 위한 장치이며, 배포 시 제거한다.

## 4. 문구 생성

**입력**: 주문서 전체

**출력**: 후보 **3건**, 각 건은 헤드라인과 서브로 분리된다

```
1. 헤드라인  겨울 감성 크로플
   서브      지금 4,500원
2. ...
3. ...
```

분리 출력의 근거는 다음과 같다. 이미지에 문구를 배치할 때 헤드라인은 크게,
서브는 작게 처리해야 하므로 단일 문자열로 전달할 경우 이미지 담당이 분할
기준을 판단할 수 없다.

**표시 선택지**: `[헤드라인만]` `[헤드라인 + 서브]`

**가격 처리 규칙**

- 사용자가 반드시 입력한다 (선택지·자연어 무관)
- 가격이 불필요한 광고(오픈·가게 홍보 등)는 **0원**으로 입력한다
- **0원인 경우 문구·이미지에 가격을 표시하지 않는다**
- **LLM 의 가격 임의 생성을 차단한다.** 미존재 가격 표기는 표시광고법 위반에 해당한다

## 5. 데이터 저장

### 5-1. DB — PostgreSQL

```
사용자 (계정)
  └─ 가게 다수 (업종 · 주소 · 상호 · 연락처)
      └─ 주문서 다수
          ├─ 생성된 문구
          └─ 이미지 경로
```

**선정 근거**

- 로그인·가게·주문서·이력이 모두 관계형 데이터에 해당한다
- GCP Cloud SQL 로 직접 연결 가능하다
- 향후 벡터 검색 도입 시 `pgvector` 확장으로 동일 DB 내에서 처리할 수 있다

**AI 페르소나 담당의 DuckDB 와 병행 운용한다.** 용도가 상이하기 때문이다. 상권
공공데이터는 1회 적재 후 읽기 전용으로 사용하는 분석 데이터이므로 DuckDB 가
적합하며, 본 서비스 데이터는 다수 사용자의 지속적인 쓰기·삭제가 발생하므로
PostgreSQL 이 적합하다.

### 5-2. 이미지 파일

DB 에 저장하지 않는다. 파일 스토리지(GCS 등)에 보관하고 **DB 에는 경로만** 기록한다.

### 5-3. 이력 활용

기존 주문서·문구·이미지를 차기 생성 시 참조한다.

| 단계 | 방식 | 적용 시점 |
|---|---|---|
| **1단계** | 최근 이력 일부를 프롬프트에 주입 | **현재** |
| 2단계 | 벡터 검색을 통한 유사 이력 조회 | 이력 누적 후 |

## 6. 기술 구성

| 구분 | 선택 | 비고 |
|---|---|---|
| 프론트 | **Streamlit** | 개발·검증용. 최종 프론트 미정 |
| 백엔드 로직 | `src/app_core/` | UI·프레임워크 비의존 |
| DB | PostgreSQL | |
| LLM | OpenAI API | 추후 변경 가능 |
| 이미지 생성 | 담당: 팀원 C | |
| 배포 | GCP | |

### 6-1. 프론트엔드 교체 가능성

Streamlit 으로 구현하더라도 향후 React 전환 시 `src/` 수정이 불필요하다.
**단, 아래 조건을 준수해야 한다.**

- 대화 로직·주문서·LLM 호출은 전량 `src/app_core/` 에 배치한다
- Streamlit 은 화면 렌더링만 담당하며, `app_core` 함수를 호출하는 데 그친다
- **`app_core` 내부에 `import streamlit` 이 존재해서는 안 된다**

`AGENTS.md` 의 기존 원칙(`app_core` 는 FastAPI 없이 단독 동작)과 동일한 규칙이다.

### 6-2. 실행 환경 — Docker

Python·PostgreSQL·의존성이 전부 컨테이너 안에 있다.

```
cp .env.example .env      # OPENAI_API_KEY 를 채운다
docker compose up app     # → localhost:8501
```

| 서비스 | 내용 | 포트 |
|---|---|---|
| `db` | PostgreSQL 16 | 5432 |
| `app` | 챗봇 UI · 문구 생성 · API | 8501 / 8000 |
| `gpu` | 이미지 생성 (GPU 필요) | 8502 / 8001 |

**구성 시 처리한 사항**

| 항목 | 처리 | 근거 |
|---|---|---|
| DB 데이터 보존 | `pgdata` 명명 볼륨 | 볼륨이 없으면 컨테이너 재생성 시 가입 계정이 소실된다 |
| 기동 순서 | `healthcheck` + `depends_on` | `app` 이 `db` 보다 먼저 기동하면 연결에 실패한다 |
| DB 주소 | compose 가 `DATABASE_URL` 을 주입 | 컨테이너 내부에서 DB 호스트는 `localhost` 가 아니라 서비스명 `db` 다 |
| 코드 반영 | 소스 디렉토리 바인드 마운트 | 코드 수정마다 이미지를 재빌드하지 않기 위함 |

**보조 명령**

```
docker compose run --rm app pytest     # 테스트
docker compose run --rm app bash       # 컨테이너 내부 작업
```

### 6-3. 설정 관리 — `.env`

API 키·DB 주소 등은 코드에 넣지 않고 `.env` 로 분리한다. `.env` 는 gitignore
대상이며, 저장소에는 값이 빈 `.env.example` 만 커밋한다.

읽어들이는 방식은 실행 환경에 따라 다르다.

| 실행 방식 | 주입 주체 |
|---|---|
| 도커 | compose 의 `env_file` |
| 로컬 (`streamlit run app.py`) | `app_core/config.py` 의 `load_env()` |

`load_env()` 는 표준 라이브러리만 사용한다. `python-dotenv` 를 도입하지 않은 것은
용도가 단순 파일 파싱에 그쳐 의존성을 늘릴 실익이 없기 때문이다.

**이미 설정된 환경변수는 덮어쓰지 않는다.** 도커 실행 시 compose 가 주입한 값이
`.env` 파일의 값보다 우선해야 하기 때문이다.

### 6-4. 배포 준비

현 단계에서 GCP 를 위해 별도 설계할 사항은 없다. 다만 다음 두 가지는 현
시점부터 준수한다.

- API 키·설정은 **환경변수로 관리** (기 적용)
- 파일 저장 대신 **DB 사용** — GCP 는 인스턴스 재시작 시 로컬 파일이 소실된다

DB 는 `DATABASE_URL` 하나로 접속 대상이 결정되므로, 배포 시 Cloud SQL 주소로
교체하는 것 외에 코드 변경이 발생하지 않는다.

## 7. 팀원용 — 실행 및 확인 방법

> 이 장은 **다른 담당자가 챗봇·문구 생성을 직접 확인**하기 위한 안내다.
> 파이썬을 설치하거나 DB 를 따로 띄울 필요는 없다. 전부 컨테이너 안에 있다.

### 7-1. 준비 (최초 1회)

**① Docker Desktop 설치 후 실행**

설치 여부는 아래로 확인한다.

```
docker --version
```

**② 저장소 내려받기**

```
git clone https://github.com/Codeit-AI10-Part4-Team4/codeit-ai10-team4-advanced-project.git
cd codeit-ai10-team4-advanced-project
```

**③ 설정 파일 생성**

```
cp .env.example .env
```

생성된 `.env` 를 열어 두 항목을 수정한다.

```
MODEL_PROFILE=openai
OPENAI_API_KEY=sk-...      ← 팀 공용 키 (별도 전달)
```

> `MODEL_PROFILE` 을 `stub` 으로 두면 API 키 없이 화면 구성만 확인할 수 있다.
> 이 경우 챗봇은 응답하지 않는다.
> `.env` 는 gitignore 대상이므로 키가 저장소에 올라가지 않는다.

### 7-2. 실행

```
docker compose up app
```

한 줄이면 PostgreSQL 과 애플리케이션이 함께 기동된다. 최초 실행은 이미지
빌드로 인해 수 분이 소요되며, 이후에는 즉시 뜬다.

기동 후 브라우저에서 **http://localhost:8501** 로 접속한다.

| 명령 | 용도 |
|---|---|
| `docker compose up app` | 실행 |
| `docker compose down` | 종료 |
| `docker compose logs -f app` | 로그 확인 |
| `docker compose run --rm app pytest` | 테스트 실행 |

### 7-3. 확인 순서

| 단계 | 화면 | 확인 사항 |
|---|---|---|
| 1 | 회원가입 | 아이디 · 비밀번호(8자 이상) |
| 2 | 가게 추가 | 업종 선택, 상호, **주소는 "서울"로 시작**해야 통과 |
| 3 | 광고 만들기 | `[광고 이미지 만들기]` / `[광고 문구 만들기]` |
| 4 | 챗봇 | 자연어 입력. 선택지 클릭도 가능 |
| 5 | 주문서 패널 | **화면 우측에서 매 턴 갱신되는 값을 확인** |
| 6 | 문구 만들기 | 필수 항목(상품·가격)이 채워지면 버튼 활성화 |

입력 예시: `교촌치킨에서 신메뉴를 출시했는데 적절한 문구를 추천해줘`

### 7-4. 주의 사항

**`.env` 수정 시 컨테이너 재생성이 필요하다.**

```
docker compose up -d --force-recreate app
```

`docker compose restart` 는 프로세스만 재시작하므로 환경변수가 반영되지 않는다.
설정을 변경했는데 동작이 그대로라면 이 문제일 가능성이 높다.

**데이터 초기화**

```
docker compose down -v
```

`-v` 는 DB 볼륨까지 삭제하므로 가입 계정과 등록 가게가 모두 사라진다.
평소에는 `-v` 없이 종료한다.

### 7-5. 주문서를 코드에서 받아 쓰는 경우

이미지 생성·품질 평가 담당은 화면이 아니라 **주문서 데이터**를 필요로 한다.
챗봇 완성을 기다릴 필요 없이 아래 값을 직접 만들어 개발할 수 있다.

```python
from app_core.schema import AdBrief, Store

store = Store(
    id=1, user_id=1,
    industry="cafe", name="연남 크로플",
    address="서울시 마포구 연남동 1-2", phone="02-000-0000",
)
brief = AdBrief(
    goal="image", product="크로플", price=4500,
    situation="신메뉴", tone="따뜻한",
)
```

전달되는 값의 형태는 다음과 같다.

```json
{
  "store": {
    "industry": "cafe", "name": "연남 크로플",
    "address": "서울시 마포구 연남동 1-2", "phone": "02-000-0000",
    "industry_note": "", "id": 1, "user_id": 1
  },
  "brief": {
    "goal": "image", "product": "크로플", "price": 4500,
    "situation": "신메뉴", "tone": "따뜻한",
    "extra": "", "with_sub": true
  }
}
```

| 항목 | 설명 |
|---|---|
| `store.industry` | `configs/industries.yaml` 의 id |
| `store.industry_label` | 사람이 읽는 업종명 (프롬프트용). `기타`면 직접 입력값 |
| `brief.price` | **0 이면 광고에 가격을 표시하지 않는다** (`brief.show_price` 로 판정) |
| `brief.situation` · `tone` | 자유 텍스트. 고정 목록이 아니다 |
| `brief.with_sub` | 서브 문구 생성 여부 |

주소는 미입력 시 `"서울"` 로 대체되므로 항상 값이 존재한다.
