# 동네 매장 광고 만들기

폰으로 찍은 사진 한 장으로, 동네 매장 사장님이 **5분 안에 바로 쓸 수 있는 광고물**을 만드는 서비스.

> 경쟁 상대는 다른 AI 서비스가 아니라 **"그냥 폰 사진 그대로 올리기"** 다.

📄 [01 타깃 사용자 및 기능 정의](docs/01_타깃사용자_및_기능정의.md) · [02 광고 규제 준수 기능 설계](docs/02_광고규제_준수기능_설계.md) · [03 기술계획서](docs/03_기술계획서_기본기능.md) · [04 넘겨줄 데이터](docs/04_넘겨줄_데이터.md)

## 사용 흐름

```
사장님 ──> 챗봇 ──> 주문서 ──> 주방 ──> 결과
 사진·말    되묻기·   사람의 말을  문구·이미지  시안 확인
            제안      구조화       생성        수정 요청
```

**챗봇과 주방을 분리한다.** 대화 방식이 달라도 주문서 이후의 생성 파이프라인은 동일하게 재사용된다.
수정도 같은 구조다 — 바꾸고 싶은 조건만 주문서에 반영한 뒤 주방을 다시 호출한다.

**주문서 형식이 둘 사이의 약속**이다 → [04 넘겨줄 데이터](docs/04_넘겨줄_데이터.md)

## 확정된 결정 (2026-08-05)

| | 선택 | 근거 |
|---|---|---|
| **아키텍처** | **FastAPI + Streamlit** | SDXL 이 수십 초 걸리는 동안 UI 가 멈추면 안 된다. `job_id` 로 비동기 접수 |
| **생성 모드** | **2종** (`preserve` · `scene`) | 먼저 한 번 끝까지 연결하고 품질을 높인다 |
| **규격** | **1080×1080 고정** | 한 규격을 제대로 만든 뒤 하나씩 추가 |
| **레이아웃** | 생성 후 **Pillow 합성** | Diffusion 이 한글을 못 그린다 |
| **대화 흐름** | **데이터(YAML)** | 질문 순서·추가가 잦을 것으로 예상 |
| **자연어 입력** | **기본 동선** | 선택지는 힌트로 함께 제시 (혼합 주도) |

## 생성 모드 — 사용자는 고르지 않는다

사진을 올렸는지로 자동 결정된다.

| 제품 사진 | 모드 | 하는 일 | 지켜야 할 것 |
|:---:|---|---|---|
| ✓ | `preserve` | 누끼 → SDXL 배경 생성 → **원본 상품 합성** | 상품 내부 픽셀 최대한 보존 |
| ✗ | `scene` | SDXL text-to-image | **"연출된 이미지" 표기** |

**공통 마무리**: Pillow 로 한글 문구·가격 배치 → 1080×1080 PNG

### 프로젝트 요구사항 대응

| 요구사항 예시 기능 | |
|---|:---:|
| 상품 이미지 → 광고 문구 제안 | ✅ |
| 광고 이미지 1 — 텍스트 입력만 | ✅ `scene` |
| 광고 이미지 2 — 레퍼런스 | ⬜ 나중에 (IP-Adapter) |
| 광고 이미지 3 — 입력 이미지 보존 | ✅ `preserve` |
| 광고 이미지 4 — 스케치 | ⬜ 나중에 (ControlNet) |

## 구간별 담당

| 구간 | 입력 → 출력 | 핵심 기술 |
|---|---|---|
| **대화·상담** | 사용자의 말·사진 → 필수 정보가 채워진 상태 | LLM · Structured Outputs |
| **주문서·API** | 추출한 값 → 검증된 주문서 | FastAPI · Pydantic · `job_id` |
| **주방·생성** | 주문서 → 문구·광고 이미지 | SDXL · rembg · Diffusers · Pillow |
| **결과·개선** | 시안 → 선택·수정·평가 | 저장 · 수정 이력 · 품질 평가 |

## 개발 순서

**각 기능을 따로 완성하기보다 작은 최소 버전을 먼저 끝까지 연결한다.**

```
1. 주문서 형식     ← 최우선. 이게 끝나야 병렬로 간다
2. 문구 1개        API 끝까지 연결
3. 사진 보존       상품 + 새 배경
4. 생성 모드       사진 없는 흐름
5. 수정·평가       챗봇 통합 테스트
```

## demo/ — 설계 데모

`demo/` 는 **설계를 보여주기 위한 데모**다. 실제 구현이 아니다.

```bash
streamlit run demo/app_chat.py
```

챗봇 흐름·분기 구조·주문서 개념을 클릭해볼 수 있다. 결과는 목업이다.

> ⚠️ 데모의 자연어 처리·금칙어 검사는 **키워드/정규식 기반**이라 유연한 입력에 대응하지 못한다.
> 실제 구현에서는 LLM 으로 대체한다.
> **데모에서 재사용할 것은 코드가 아니라 설계**(주문서 형식·대화 흐름·레지스트리 구조)다.
