# 동네 광고 만들기

동네 가게 사장님이 **짧은 대화만으로 광고를 만들고, 게시하기 전에 그 동네 손님에게 먼저 물어보는** 서비스.

> 광고를 만들어 주는 AI는 이미 많다. 우리가 만든 건 **게시하기 전에 팔릴지 같이 물어봐 주는 쪽**이다.

📄 **[최종 보고서 (PDF)](docs/4팀_고급프로젝트_보고서.pdf)** — 문제 정의부터 검증 결과·한계까지 전체 기록

Codeit AI 10기 고급 프로젝트 · 4팀 (김건오 · 고귀한 · 이아인 · 이수호) · 2026.08.03 ~ 08.28

---

## 무엇을 푸는가

생성형 AI로 광고를 **만드는 일**은 이미 쉽다. 어려운 건 그다음이다.

- **보기 좋은 광고와 팔리는 광고는 다르다** — 예쁘게 나왔다고 손님이 오지 않는다
- **그 차이를 미리 알 방법이 없다** — 광고비를 쓴 뒤에야 안다
- **AI는 사장님이 말한 적 없는 사실을 지어낸다** — 가격·혜택을 창작하면 표시광고법 위반이다

그래서 서울시 상권 데이터로 **그 동네 손님을 구성해** 게시 전에 반응을 받고,
광고에 들어가는 **사실은 사장님이 말한 것으로만** 제한했다.

---

## 사용 흐름

```
① 가입·가게 등록      주소만으로 그 동네 상권 데이터가 붙는다
② 결과물 선택         감성형(글자 없음) · 감성형(문구) · 정보 포스터
③ 사진 유무 선택      고른 쪽에 맞는 업로드 칸만 열린다
④ 짧은 대화           상품·가격·상황·말투가 주문서에 쌓인다
⑤ 문구 3안 + 손님 반응 점수가 아니라 고칠 수 있는 문장으로 온다
⑥ 광고 완성·저장      1080×1080 PNG
```

**결과물을 대화보다 먼저 고른다.** 글자 없는 사진만 원하는 사장님은 ③~⑤를 건너뛴다.
순서가 뒤면 다 끝난 뒤에야 불필요한 단계였음이 드러난다.

## 빠른 시작

```bash
pip install -e ".[dev]"      # src 레이아웃 — import 는 app_core / api (src. 접두어 없음)
cp .env.example .env         # 키와 프로필을 채운다
python -m api                # http://127.0.0.1:8000/docs
streamlit run app.py         # 화면
```

> ⚠️ `uvicorn api.main:app` 으로 직접 띄우지 말 것. `config.load_env()` 를 안 거쳐서
> **서버만 `.env` 를 못 본다** — 주소→좌표 변환이 죽는다. `api/__main__.py` 가 그걸 먼저 읽는다.

| 환경 변수 | 뜻 |
|---|---|
| `MODEL_PROFILE` | `stub`(키 없이 화면만) · `openai`(실제 대화·문구) |
| `IMAGE_PROFILE` | `local`(sd-turbo, GPU) · `openai`(gpt-image-2, GPU 불필요) |
| `OPENAI_API_KEY` · `KAKAO_REST_KEY` | 각각 LLM·이미지, 주소→좌표 |
| `SESSION_SECRET` | 로그인 토큰 서명 키 (비우면 재시작 시 로그인이 풀린다) |

품질 게이트 (CI와 동일):

```bash
ruff check src tests && ruff format src tests && mypy && pytest
```

## 구조

```
src/api  ──depends on──>  src/app_core
```

**`app_core` 는 `api` 를 절대 import 하지 않는다.** FastAPI 없이 단독 실행·테스트가 가능해야 한다.
라우터는 thin 하게 — 요청 검증 → `app_core` 호출 → 응답 변환까지만.

| 구간 | 입력 → 출력 | 핵심 |
|---|---|---|
| 대화·NLU | 사장님의 말 → 채워진 주문서 | 질문 선택은 코드, 문장은 LLM |
| 문구 | 주문서 → 후보 3개 | 생성 후 코드 검사로 위반 폐기 |
| 손님 패널 | 주문서 + 상권 → 반응·걸림돌 | 정량은 코드, 서사는 LLM |
| 이미지 | 주문서 + 사진 → 1080×1080 PNG | 연출은 AI, 글자는 Pillow |

`app_core/schema.py` 의 **주문서(AdBrief)** 가 네 파트를 잇는 단일 계약이다.

## 설계 결정과 근거

| 결정 | 근거 |
|---|---|
| **무엇을 물을지는 코드가 정한다** | 모델에 맡겼더니 프롬프트의 JSON 예시를 값으로 복사해 같은 질문을 반복했다. 코드가 고르면 그 실패가 구조적으로 불가능해진다 |
| **가격은 세 상태로 나눈다** | 미확인 / 표시 안 함 / 실제 금액. 뭉뚱그리면 빈칸을 모델이 채우고, 그 순간 표시광고법 위반이다 |
| **수량 오인은 프롬프트가 아니라 코드로 막는다** | "2,000원에 2+1" — 금액은 맞는데 세 캔이 2,000원으로 읽힌다. 틀린 게 금액이 아니라 *무엇의 금액인가* 라 금액 검사로는 안 잡힌다 |
| **글자는 AI가 아니라 코드가 쓴다** | Diffusion 이 한글을 못 그린다. 가격·상호·주소·전화번호는 Pillow 가 입력값 그대로 새긴다 |
| **물건이 둘 이상이면 원본을 지킨다** | rembg 가 커피 한 잔을 부스러기로 판단해 지웠다. 진짜 부스러기는 0.2%, 사라진 커피는 2.6% |
| **정량은 코드, 서사는 LLM** | 점수·순위·신뢰도는 결정적 함수가 계산하고, 모델은 "왜 그렇게 느꼈는지"만 쓴다 |
| **잡음보다 작은 차이로 순위를 뒤집지 않는다** | 재실행 흔들림이 0.7점. 그 3배 안이면 "비슷합니다"라고 말한다 |
| **고치기 전에 재는 도구부터 만든다** | 프롬프트를 다섯 번 고치는 동안 판단 근거가 전부 육안이었다 |

자세한 이력은 [DESIGN_DECISIONS.md](docs/DESIGN_DECISIONS.md) 와 보고서 8장.

## 검증 결과

| 항목 | 조건 | 결과 |
|---|---|---|
| NLU 정보 추출 | 골든셋 80건 × 3회 | **100%** (첫 측정 83%) |
| 문구 가격 규칙 위반 | 주문서 16건 × 3회 = 후보 144건 | **0 / 144** |
| 근거 없는 주장 | 같은 144건 키워드 검사 | 4건 → **0건** |
| 대화 반복 질문 | 재현 시나리오 5회 | 5/5 → **0/5** |
| 손님 패널 가격 쏠림 | 역삼 1개 상권, 분류 방식 개편 전후 | 12/12 → **1/12** |
| 자동 검사 | 단위·통합 | **857개 전부 통과** |
| 카페 통합 경로 | 사진 유무 2 × 결과물 3 | **6/6 결과 파일 생성** |

> 이 수치들은 **정해진 조건에서 잰 것**이다. 실제 구매 전환이나 매출 상승을 증명하지 않는다.
> 일부 자동 검사는 비용 때문에 실제 AI 호출 대신 모의 응답을 쓴다.

## 남은 과제

1. **순위가 정보를 덜 준 광고를 뽑아준다** — 금액만 뺐을 때 30→46점, 39→45점. 측정 오차 0.9점으로는 설명이 안 된다. 가격을 안 적으면 "비싸다"는 지적을 받을 일이 없기 때문
2. **가상 손님이 사람과 얼마나 닮았는지 아직 못 쟀다** — 상관계수를 잴 코드는 있으나 정답 칸이 비어 있다
3. **주소 정확도를 화면이 알려주지 않는다** — "서울시 마포구"만 넣어도 등록되는데 화면은 확정된 상권처럼 말한다
4. **공개 배포 전 보안** — 토큰 만료·폐기, 속도 제한, 결과 이미지 경로 인증
5. **검사 어휘 밖의 생성** — "입안에서 사르르 녹는" 같은 정성적 표현은 아직 안 걸린다
